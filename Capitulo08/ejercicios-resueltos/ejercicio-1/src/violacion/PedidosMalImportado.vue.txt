Este archivo tiene extensión .txt a propósito: es la versión PROHIBIDA del componente, la
que el ejercicio pide escribir para comprobar que la regla de ESLint la bloquea. Se deja
fuera del grafo de compilación para que `npm run build` siga siendo una validación limpia
del código correcto.

Para reproducir el fallo de lint, se copia el contenido a
src/modules/pedidos/components/ListaPedidos.vue y se ejecuta `npm run lint`.

---
<script setup>
import { usePedidos } from '../composables/usePedidos.js'

// IMPORTACIÓN PROHIBIDA: entra a un archivo interno del módulo clientes,
// saltándose su index.js. Esto es lo que la regla no-restricted-imports debe rechazar.
import { useClientes } from '@/modules/clientes/composables/useClientes.js'

const { pedidos } = usePedidos()
const { nombrePorId } = useClientes()
</script>

<template>
  <ul>
    <li v-for="pedido in pedidos" :key="pedido.id">
      {{ nombrePorId(pedido.clienteId) }}
    </li>
  </ul>
</template>
---

Salida esperada de `npm run lint` con la regla activa:

  src/modules/pedidos/components/ListaPedidos.vue
    5:1  error  '@/modules/clientes/composables/useClientes.js' import is restricted from
                being used by a pattern. Importa desde el index.js del módulo, no de sus
                archivos internos.

  1 problem (1 error, 0 warnings)

Pasa a verde cuando la línea se corrige a:

  import { useClientes } from '@/modules/clientes'

No vale comentar la regla ni agregar eslint-disable: eso convierte la frontera en una
sugerencia y el acoplamiento vuelve a entrar por la puerta de atrás.
